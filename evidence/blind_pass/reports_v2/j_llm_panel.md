## Findings, ranked

### 1. HIGH — The 💬 Debate chip's attached ScreenContext never reaches the model; the UI says it does
`app.py:1469-1488` (`render_debate_chip`) stores the context in `st.session_state.debate_attached_context`. The only reads are `app.py:6531-6537`, which render "💬 **Considering:** {looking_at}" plus a "Full evidence" expander. The prompt is built at `app.py:6661-6673` from `build_context(...)` + chat attachments; `debate_attached_context` is never appended, and `build_context` (1786-2240) contains no draft-board section at all. `screen_context.UNIVERSAL_DEBATE_HELP` (40-43) tells the user "Open The Prytaneum with the current screen's evidence and context", and the comment at 6524-6528 states the banner "is meant to read as 'Debate already understands what I was looking at'". Only the Trade Calculator seeds the question (`app.py:4619`, 4643/4645 write `question_input`). `test_debate_chip_wiring.py:81-93` asserts the chip never writes `question_input`, but nothing asserts anything attaches the context at ask time.
**Failure scenario:** user on the clock at 3.01 clicks 💬 on Draft Room, sees "Considering: On the clock for pick 3.01" and the 8-candidate evidence in the expander, types "Lamb or Collins here?". Quant/Beat/Contrarian/Moderator receive roster, universe, league rosters — nothing about the draft, the candidates' values, or the 22-pick wait. The Moderator produces a BUY/SELL/HOLD/WAIT verdict from general knowledge; the user reads it as a judgment on the evidence they were shown. Same for Matchup, Free Agents, League and Mock Draft chips. (Also: `draft_state.clear_league_derived` clears `draft_room_*`/`mock_draft*` keys but not `debate_attached_context`, so the banner persists across a league switch.)

### 2. HIGH — `_match_candidate`'s substring fallback returns the highest-ranked name mentioned, inverting a "X over Y" Caller
`pick_debate.py:626-629`: after an exact-match miss, it iterates candidates in board order and returns the first whose name is contained in the RECOMMENDATION text. Verified against real names from the 3.01 board (CeeDee Lamb is candidate 1, Nico Collins candidate 2):
- `RECOMMENDATION: Nico Collins over CeeDee Lamb` → **CeeDee Lamb**, `best_alternative` = Nico Collins
- `Nico Collins, not CeeDee Lamb` → CeeDee Lamb; `Not CeeDee Lamb` → CeeDee Lamb; `Either Nico Collins or CeeDee Lamb` → CeeDee Lamb; `CeeDee Lamb — no wait, Nico Collins` → CeeDee Lamb; a one-character fragment `D` → CeeDee Lamb.
The docstring (615-619) claims it "returns None (never a guess) if nothing lines up"; it guesses whenever two things line up. The module docstring (18-21) presents this lookup as the structural guarantee that the displayed decomposition is deterministic — it is, but for the wrong player.
**Failure scenario:** Caller writes "RECOMMENDATION: Nico Collins over CeeDee Lamb" (ordinary LLM phrasing despite the "copy exactly" instruction). Draft Room renders `## Recommendation: CeeDee Lamb`, his necessity badge, his metric cards, and "Best alternative: Nico Collins" — the opposite of the Caller's call, with `why`/`key_factor` text arguing for Collins beneath a Lamb headline.

### 3. HIGH/MEDIUM — The recommendation panel renders the withheld survival family to the person
`pick_synthesis.withheld_fields()` (626-657) withholds `survival_probability`, `opportunity_cost`, `expected_value_of_waiting`; the evidence block tells the chairs the estimate "is WITHHELD … failed its calibration check" and `draft_board_ui` (813-814) redacts it. But `app.py:_render_pick_metrics` (1509-1594) renders "Survival to Next Pick (%)" as `round(rec.survival_probability*100)%`, plus `opportunity_cost` and `expected_value_of_waiting` cards unconditionally, and the Draft Room prints `st.caption(f"Survival: {alt_survival}")` for the best alternative (5660-5661; metrics at 5655 and mock 5229). `grep withheld|survival_is_presentable app.py` → no hits. `test_withheld_propagation.py` covers `format_snapshot_for_llm`, the diff, the prompts and `screen_context`, not this panel. In the real snapshot every candidate carries a value (Lamb 0.602, opp cost 48.35, EVW 67.88).
**Failure scenario:** the board card says "22 pick(s) come before your next turn — the survival estimate is withheld"; the debate's WHY says "22 picks"; the recommendation card directly below says **Survival 60%, Opportunity Cost 48.4, Expected Value If You Wait 67.9**. The person reasons from the number the engine's own calibration evidence says is wrong (top candidate predicted 0.81, observed 0.45 per the code's own comment).

### 4. MEDIUM — The Strategist is still told to build its case from survival odds it is not given, and told the pick count is "the only availability quantity" while a second one is supplied
The #52 repair edited the enumerated list and the KEY FACTOR example, but the live `STRATEGIST_SYSTEM_PROMPT` body still reads (231-232) "…a real positional cliff, a severe survival collapse, heavy denial risk…" and (243-245) "…has a **low survival probability** because of a run or opponent need, and the best alternative has **comfortably high survival odds**. Make that case explicitly, referencing the specific numbers you were given." `test_withheld_propagation` checks only the "19% survival" example and the Skeptic's "survival model" phrase. Separately, `_survival_clause` (193-197) says intervening_picks is "the only availability quantity you are given", yet `_format_candidate` 541-548 prints "~4.87 WR pick(s) expected before then" and a forfeit of 30.5 — `position_expected_taken` is the sum of the same normalised take probabilities `estimate_survival` uses (`draft_strategy.positional_forfeits` 371-376: "the same model estimate_survival uses, through the same seam"). Also names a "lineup-eligibility" term (218) that the code comments say was retired.
**Failure scenario:** instructed to reference "low survival probability" figures, the Strategist derives one from "22 picks" — exactly what the evidence block forbids — and the Caller carries it into KEY FACTOR; the withholding is defeated by the prompt that surrounds it.

### 5. MEDIUM — Injury status never crosses the snapshot boundary; the Skeptic prompt asserts the engine doesn't know it
`CandidateSnapshot` has no injury field; `_format_candidate` prints none; the Skeptic prompt (254-256) says "these numbers don't know about … a player's specific injury history". The board row does carry `injury_status` and prices it (availability haircut #191, `health_penalty`). At 3.01 the priced pool held **17 IR and 5 PUP players** (457 priced rows); e.g. Jordyn Tyson WR IR, `risk_adj=0.0`, `availability_basis=rule_floor` — so the payload for such a player reads "risk +0.0" with no injury line (the haircut already lowered projected points, so the penalty path returns 0.0 at `draft_room.py:460`).
**Failure scenario:** late rounds, when negative-UV rows are what remains, an IR player enters the narrowed set; the chairs see "risk +0.0", a season projection, and a PREFERRED necessity label and cannot say he is on IR; the Caller recommends him; the recommendation card has no injury field either.

### 6. MEDIUM — Failed/cut-off chairs are reported only as a one-rerun toast; the persistent panel shows a clean recommendation; CONFIDENCE is unvalidated
`debate_result.errors` is consumed only by `notify()` inside the click handler (`app.py:5617-5618`, mock 5182-5183). The persistent block (5620-5680) renders headline, confidence, why, metrics and reports, never `errors`. `parse_caller_verdict` (589-611) accepts any CONFIDENCE value; my fragment `CONFIDENCE: Unan` rendered as "Confidence: Unan" with `why=""`, and a percentage would render verbatim despite the prompt forbidding it.
**Failure scenario:** the Caller's output is cut at the provider cap after RECOMMENDATION/CONFIDENCE; the toast says "cut off" once; every later rerun on the same pick shows "Recommendation: X — Confidence: Unan" as a finished verdict. Likewise a Strategist that failed (⚠️ key missing) leaves a headline with no visible sign unless the expander is opened.

### 7. MEDIUM — "WHAT CHANGED SINCE THE LAST SNAPSHOT" has no anchor, and the user's own picks read as board movement
`previous_snapshot` is whatever board was last *debated* (`app.py:5580/5586`), possibly rounds earlier; the section header (`pick_debate.py:573-582`) states neither its pick label nor how many picks separate the two. Diffing seat 1's 1.01 board against its 3.01 board (real run) emitted e.g. "Kenneth Walker: rank moved by -23 (need_bonus: -4.0, team_acquisition_value: -3.63, positional_forfeit: -73.82, pick_necessity: -6.0)" — all consequences of the user's own two picks (roster need filled, next-gap geometry), not of anything rivals did. The withheld-field filter in `diff_snapshots` works (no survival deltas appeared). League switching does clear `draft_room_last_snapshot` (L-06), so this is within-league only.

### 8. MEDIUM-LOW — Draft Room seed hands the Prytaneum undefined units and a verdict shape that cannot express a pick
`build_draft_room_context` (screen_context 111-153) emits "acquisition value 121 UV pts" and "Decision regime: contested." No Prytaneum system prompt defines UV points or a decision regime (`grep "UV pts|universal value|acquisition value" llm_engine.py` → nothing), while the same context carries Draft Sharks' 0-100 trade values. The Moderator's block is RECOMMENDATION: BUY/SELL/HOLD/WAIT. And `default_trigger_mode="followup"` whenever any prior full debate exists (6553-6554), so a draft question routes to the Moderator alone with a week-old trade debate's reports as "already-established context". (This only matters via the Trade Calculator-style seeding today, since #1 means the Draft Room seed is not actually sent.)

### 9. LOW-MEDIUM — Silent truncations in `build_context`
Chat attachments `a['text'][:4000]` (6671) with no notice to model or user (popover says only "Ephemeral"); captions `captioned[:20]` (2216); pinned messages `[:400]` (1934). **Scenario:** a 12 KB CSV of trade offers is attached; the Quant sees the first third and states "the best offer in your file is …".

### 10. LOW — `draft_history` cannot reproduce what was shown (write-only today)
`_CANDIDATE_EVIDENCE_FIELDS` (73-87) omits 28 of CandidateSnapshot's fields, including `denial_value` (while keeping `denial_team`), `survival_basis`/`denial_basis`, `depth_exposure`, `displacement_adj`, `consensus_rank/tier`, `opportunity_cost`. Stored `tav 121.47 = uv 112.75 + need 8.72` leaves an unattributable residual whenever depth/displacement are non-zero, and `survival_probability` is stored without the companion the dataclass calls REQUIRED. Nothing reads these records yet (`app.py` only calls `record_snapshot`), so no user-facing failure — latent.

### 11. LOW — Failed-chair error strings are replayed into CONVERSATION MEMORY
`build_context` 1844-1857 filters only `summary`/`notice`; a "⚠️ Claude request failed: {exc}" quant message is replayed (fenced, labelled) into every later prompt across providers — the cross-provider exception forwarding `UNAVAILABLE_REPORT` (llm_engine 674-705) was written to avoid. `find_last_debate` correctly skips such rounds for follow-ups.

### Style-only (no failure scenario)
Unrounded floats in the evidence ("bpa 111.49000000000004"); `bpa_source`/`confidence` printed as raw tokens ("points_vor_sleeper_season_scored, confidence: 85.0") with no scale stated.

## Null results (checked, held)
On the real 47-candidate board: no `None` reached the text as "None"/dash/zero — every absence guard in `_format_candidate` was exercised or correctly dormant (all bases labelled: depth `vacant`/`no_surplus` stated as NOT a measurement, displacement `measured`, denial `measured`, consensus present for all). Strategist user prompt == evidence byte-for-byte; three distinct system prompts; Skeptic/Caller receive evidence + `_report_for_handoff`-protected reports. `diff_snapshots` drops withheld deltas. Prytaneum seed substitutes the pick count for survival. `untrusted.fence` strips forged markers and `CONTRACT` is in every Prytaneum prompt. `activate_league` clears Draft Room debate state (L-06).
